# Project instructions

- Use `PLANS.md` as the authoritative implementation and acceptance tracker. Reconcile its completed items with current evidence before resuming work; keep rationale in `NOTES.md` and do not duplicate progress checklists elsewhere.
- This project creates an Apple silicon macOS 26+ local desktop app. Keep the subtitle view independent from the controller and other video applications. Keep caption playback transparent; an empty visible window has a light-gray guide, and unlocked positioning mode exposes the interactive bounds.
- Use Node.js 26.5+ / npm 12.0.1+, the committed npm lockfile, and Python 3.13 through `uv` with `uv.lock`. Packaging stages `.venv`, backend, and native helpers through `scripts/stage-runtime.mjs` into versioned `~/Library/Application Support/kotonoha/runtime/` snapshots and records the selected root in `Contents/Resources/runtime.json`. Do not link packaged runtime dependencies back into the protected Documents checkout. This remains a local development build using the installed base Python and NeMo executable.
- `npm run build` checks frontend types and builds Vite. `npm test` runs finite scripted UI tests. Backend checks are `uv run --locked python -m pytest -q`, `uv run --locked ruff check backend`, and `uv run --locked ruff format --check backend`. Native verification is `./native/build.sh --verify`; inspect packaged architecture with `npm run check:architecture`.
- `./scripts/build-app.sh` is the single-command local app builder after system-tool installation; `--check` only diagnoses prerequisites. Preserve its locked setup, explicit `npm run prepare:models`, separate `release/build-*/` output, existing-app refusal, and selected-artifact architecture check. Run `node --test tests/*.test.mjs` for desktop and build-orchestration regressions. Use `KOTONOHA_SMOKE_APP` to smoke the actual builder output rather than the legacy default package.
- Do not start real system audio capture during automated checks. `native/bin/audio-capture --check` never prompts. Actual capture begins only from an explicit user Start action.
- Keep permission setup separate from translation: only the explicit guide action invokes `--request-permission` through authenticated `POST /api/capture/permission`. That command never creates a stream or loads models. Capture itself only preflights access; route `capture_permission_required` to the localized guide, and retain an explicit permission-request retry after settings-first setup or request failure.
- Keep initial and retry permission requests as full-width red buttons above auxiliary dialog actions. Preserve the separate permission-check action; do not reduce retry to a small text link.
- Preserve the PCM contract: stdout contains only little-endian 16 kHz mono PCM16; stderr contains diagnostics. Preserve odd-byte remainders between pipe reads and drain output during shutdown.
- Keep both local services on loopback, authenticate HTTP/WebSocket clients, keep credentials in Electron main, and do not log WebSocket query tokens. Own and terminate the Python process group on quit.
- The NeMo launch must enable token-silence endpointing. Use the pinned Hy-MT2 checkpoint in `backend/config.py`, its own chat template and EOS, full English target-language names, and no system prompt. Keep temperature 0.7, top-p 0.6, top-k 20, repetition penalty 1.05, and the 512-token subtitle output cap; report cap exhaustion rather than publishing partial text. Do not apply TranslateGemma's structured content or `<end_of_turn>` override. Preserve the final commit and translation drain before reporting stopped.
- Keep models in shared per-user caches: the pinned Hy-MT2 snapshot in the standard Hugging Face Hub cache, and `nemotron-3.5` in the installed NeMo cache. Honor standard cache environment overrides. Only explicit `npm run prepare:models` downloads models; readiness stays offline and verifies the pinned snapshot/all weight shards or the exact artifact/revision/size from the installed NeMo model index. Do not override NeMo with a workspace model directory or stage any models through `scripts/stage-runtime.mjs`. Preserve older model folders, snapshots, and app builds. Users clone and build on their own Macs; keep prerequisites in both READMEs.
- Keep the periodic commit interval in Settings alongside interface `Language`; persist `commitIntervalSeconds` (5/10/15/20/30, default 15) and pass `commit_interval_seconds` on explicit Start. It applies per session; preserve 600 ms natural endpointing and the final stop drain independently.
- Keep models and generated builds ignored. Preserve only the latest 1,000 transcript entries in memory; no automatic recording or transcript file writes.
- Default new subtitle settings to 30 px with original text off in both desktop and renderer, preserving saved preferences. Keep the interface-language label as `Language` in both UI languages for discoverability. Controller toggle descriptions and row whitespace must remain inert; only the switch itself (or keyboard activation on it) changes state. Preserve accessible names and focus indication.

- Keep `uiLanguage` independent of source/target languages, default it to Japanese, and preserve old kotoba preferences through `desktop/preferences.mjs` without overwriting the legacy profile. Localize the controller, subtitle toolbar, menus, and backend status/errors; never localize transcript content as UI text.
- Package `release/kotonoha-darwin-arm64/kotonoha.app` with the tracked `assets/kotonoha.icns` and Retina menu template images. Preserve the native capture bundle identity for recording permissions. The desktop smoke uses a temporary profile and port 8767; keep production on 8765.
- Use `desktop/window-layout.mjs` for startup work-area placement: controller at most 480×640 with at least 16 px separation above subtitles; preserve subsequent user moves/resizes. Keep the parent app regular and Dock-visible with a kotonoha application menu. Activate it only for user restoration, never for background errors or caption display; the native recording helper remains an agent app.
- Start the overlay visible and locked after its content loads; keep hidden smoke runs invisible and skip initial display after startup errors; use the floating window level, not screen-saver. Locked mode must ignore mouse input, disable drag regions and focusability, and release existing keyboard focus. Hide/reset it on start, stop, error, and quit; after startup, show automatically only after a translated caption. Background errors must not focus the controller. Guard destroyed/quitting windows through `desktop/window-actions.mjs`.

- After menu-template changes, run `xcrun swift -module-cache-path .scratch/icon-module-cache scripts/check-menu-icons.swift` with a 30-second limit. Verify transparent margins and matching silhouettes, not just raster size/DPI; AppKit already scales a Retina bitmap when its logical point size is assigned.
